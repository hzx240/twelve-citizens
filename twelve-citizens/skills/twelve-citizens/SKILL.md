# 十二公民 · 计划审计

对**已经生成**的计划开庭。十二个席位性格不同、互不见面、同一次发出；全部回到之后，才由审判长判定要不要改。

结构只借陪审团：独立第一轮投票，票数不是结论，没有原文的成见作废，一条能指出计划矛盾的少数意见可以推翻看起来一致的计划。不要扮演电影情节，不要引用对白，不要写成刑事案件。

## 禁止

- 禁止自己扮演十二个席位或审判长。必须真正调用 Task。
- 禁止合并席位，禁止少开，禁止用一次回复里的十二段独白冒充。
- 禁止在十二份意见到齐之前召唤审判长、写裁决、或暗示「大概会怎么判」。
- 禁止把某一席的意见写进其他席位的提示词。
- 禁止在审计过程中修改计划、写实现、或执行计划。
- 用户没有明确要求审计时，不要开庭。写计划、普通审阅、问一句话，都不要启动本技能。

席位职责、输出标题、两份提示词模板在 [jurors.md](jurors.md)。开庭前先读完它。

## 开庭条件

同时满足才开庭：

1. 用户明确要求审计、压力测试、或用十二公民 / 陪审团看这份计划。
2. 已经有一份具体计划：对话里的计划全文，或用户指出的文件。没有计划就停下来问要审哪一份，不要现编一份再审。

计划指 Cursor 计划、markdown 计划，或对话里刚生成的计划正文。同一套流程。用户一次给了多份又没指定时，先问审哪一份。

## 1. 立卷

写一份案卷，十二个席位读**同一路径**。不要把计划改写成十二个不同的摘要。不要把你自己的评价写进去。

- 计划已经在一个文件里：案卷只放用户目标的原文、该文件的绝对路径，并写明计划全文以该文件为准。
- 计划只在对话里：把计划原文完整放进案卷，不要省略。
- 用户目标用用户的原话。对话里没有就写「目标未给出」，不要编目标。
- 案卷放在系统临时目录的 `twelve-citizens-<id>/case.md`，不要放进用户的 git 仓库。

## 2. 十二席同时出庭

在**同一条消息**里发出 12 次 Task。参数以 [jurors.md](jurors.md) 为准。

- `subagent_type`：`generalPurpose`。不要改成 planner、code-reviewer 或其他专家类型，性格来自席位提示词。
- `description`：用该席位规定的名称，十二个名称必须彼此不同。
- 不传 `model`，除非用户点名模型。不传 `environment`。第一次不要传 `resume`。
- `run_in_background`：false。用户处于 Multitask Mode 时必须为 true。
- 提示词：案卷路径 + 该席位全文 + jurors.md 里的统一输出格式。提示词写明只读：可以读案卷和仓库来核对计划里的具体说法；禁止写入、创建文件、执行计划、运行会改变系统的命令。

某一席调用失败时，立刻把缺的席位补发出去。后补的提示词里仍然不要出现已经返回的意见。运行环境拒绝一次性发出十二席时，只补发调用，不要自己补写缺席的投票。

## 3. 等候

`run_in_background` 为 false 时，等这一批全部返回，再进入下一步。

为 true 时：本回合到此为止。不要轮询，不要提前归纳。之后每个回合只登记到席的原文。十二份到齐的那个回合，才召唤审判长。

某一份没有 `## 投票`，或整席失败：用该席的 agent id `resume` **一次**，只要求按原席位和统一标题重写，不换性格，不追加任务。重试后仍没有，记为缺席。沉默不是「通过」。

## 4. 审判长

十二份都已返回或已确认缺席之后，单独再发 **一次** Task。不要和陪审员放在同一条消息里。

把十二份**原文**放进审判长提示词。可以去掉工具元数据，不得改写、删减或预先合并异议。归纳是审判长的工作。

审判长也是 `generalPurpose`，只读，名称用 `审判长·核实修改`。判定标准用 jurors.md 里的审判长提示词，不要临时放宽。

审判长输出缺了 `# 裁决` 或 `# 有没有必要修改` 时，resume 审判长一次，只补格式。

## 5. 父代理核对引用

审判长返回后，只做引用核对：

- 「必须修改」和「审判长补遗」里的引用，要能在案卷或计划文件里找到；「计划未写」必须指出应出现在哪一节。
- 对不上的条目从必须修改里去掉，并在交付时写明去掉了哪一条。
- 不要新增必须修改，不要把审判长的「维持」改成「退回」，也不要另写一套更温和的意见。

然后删除临时案卷目录。

## 6. 交付

用中文，先给裁决。十二份原文不要铺开；每席只留「一句话」。用户要某一席全文时再给。

提到席位或审判长时，用 Task 返回的 id 做成链接，链文字用该席的 `description`。

```markdown
# 十二公民 · 计划裁决

## 裁决
维持原计划 / 必须修改后才能执行 / 放弃并重做

## 有没有必要修改
一句话。

## 必须修改
- 来源：
  引用：
  问题：
  不改会怎样：
  改成：

## 建议修改
不改也能按原计划执行。

## 已驳回
- 来源：
  要点：
  为什么不改：

## 各席一句话

## 投票分布，仅供对照
通过 / 退回修改 / 放弃重做 / 作废 / 缺席

## 引用核对
对不上而已删除的条目。没有就写「无」。
```

## 7. 要不要改计划

默认只交付裁决，不改计划文件。

用户明确要求按裁决修改时：只改「必须修改」里留下的条目。建议修改列出来，但不写进计划，除非用户同时要求采纳建议。计划只在对话里时，给出替换后的对应段落，不要擅自新建文件。
